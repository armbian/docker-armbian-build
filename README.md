# docker-armbian-build

## Purpose of This Repository

Build and publish the Docker images that Armbian's build framework and infrastructure rely on. Each image is produced by a GitHub Actions workflow that generates its `Dockerfile` at build time and pushes the result — multi-arch — to the [GitHub Container Registry](https://github.com/orgs/armbian/packages).

## Published images

| Image | Purpose |
| --- | --- |
| `ghcr.io/armbian/docker-armbian-build:armbian-<os>-<release>-<arch>-latest` | Build environments consumed by [`armbian/build`](https://github.com/armbian/build) (`./compile.sh docker …`). Matrix covers Ubuntu/Debian releases across `amd64`, `arm64` and `riscv64` (native runners). |
| `ghcr.io/armbian/repository-update:<release>-<arch>` | Internal package-publishing pipeline images (based on Aptly). The matrix is generated on the fly from `armbian/build`'s `config/distributions/*/support` + `architectures`, skipping releases marked EOS. |
| `ghcr.io/armbian/apt-cacher-ng:latest` (also `:trixie`) | Debian-trixie `apt-cacher-ng` (3.7.x), the caching apt proxy used by `armbian-config`'s `module_aptcacherng`. |
| `ghcr.io/armbian/git_cdn:latest` | [`git_cdn`](https://gitlab.com/grouperenault/git_cdn) — caching git+HTTP(S) proxy used by `armbian-config`'s `module_git_cdn`. Built multi-arch from upstream sources (upstream only ships x86-64). |

All images are built with Docker Buildx + QEMU and pushed for `linux/amd64` and `linux/arm64` (build-framework images additionally for `linux/riscv64` on native RISC-V runners).

## How the matrices stay current

- The **build-framework** matrix (`update_docker.yml`) is defined explicitly in the workflow and pins the current set of supported `os` / `release` / `arch` / `runner` tuples. `Dockerfile`s are generated by invoking `./compile.sh generate-dockerfile` from `armbian/build`, so the installed package set tracks upstream. Trixie/Resolute images additionally get GCC 13 (native + cross toolchains) side-loaded to keep older vendor sources buildable.
- The **automation** matrix (`build-docker-images.yml`) is derived at run time by reading `armbian/build`'s `config/distributions/*/{support,name,architectures}` files, so newly supported releases appear automatically and EOS ones drop off.

## Reliability

- A watchdog workflow runs every 15 minutes and re-runs failed jobs of the daily `build-docker-images` and `update_docker` workflows (up to 3 attempts), so a transient registry, mirror or network hiccup self-heals without human intervention.
- [`.github/dependabot.yml`](.github/dependabot.yml) keeps the GitHub Actions used across the workflows up to date.

## Built with

- **GitHub Actions** (YAML workflows under `.github/workflows/`) orchestrating the whole pipeline.
- **Docker Buildx** + **QEMU** for multi-arch builds and pushes to **GHCR**.
- **Bash** inside workflow `run:` steps to generate `Dockerfile`s, drive `gh`/`jq` API calls, and derive the automation build matrix from `armbian/build`.
- **Python 3.12** + **Poetry** to build the `git_cdn` wheel from upstream source before packaging it into a slim runtime image.
- Base images from **Debian** (`trixie`, `bookworm`) and **Ubuntu** (`jammy`, `noble`, `resolute`), plus **Aptly** 1.6.2 for the repository-update image.

## CI

This repository is entirely CI-driven; there is nothing to build locally. For live status of every workflow and run in this repo, see the Armbian CI overview:

- **CI dashboard:** <https://actions.armbian.com/?repo=docker-armbian-build>

All workflows can also be triggered on demand from the GitHub Actions tab via *Run workflow*.
